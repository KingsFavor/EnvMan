# EnvMan 디자인 핸드오프

디자이너 전달용 문서입니다. 현재 구현은 기능을 검증한 초안이며, 디자인과 UX는 이 문서를 바탕으로 처음부터 다시 설계합니다.

- 작성일: 2026-10-07
- 대상 플랫폼: macOS 14 (Sonoma) 이상, 네이티브 앱
- 코드: https://github.com/KingsFavor/EnvMan
- 기능 상세 명세(기존): https://claude.ai/code/artifact/ef0fb056-4462-48b3-8d3b-a5840670eeb4

> 문체 규칙: 모든 산출물에서 긴 대시(em dash, en dash)와 가운데 점을 쓰지 않습니다. 콜론, 쉼표, 괄호, 슬래시로 대신합니다. 앱 안의 문구는 한국어가 기본입니다.

---

## 1. 제품 한 줄 정의

환경변수와 API 키 같은 민감한 값을 기기 안에 암호화해 보관하고, 필요할 때 한 번에 복사해서 붙여넣는 macOS 앱입니다.

- 모든 데이터는 로컬에만 저장되고, 값은 평문으로 디스크에 남지 않습니다.
- 비밀번호 없이도 목록(네임스페이스와 키 이름)은 볼 수 있고, 값을 보거나 복사할 때만 잠금을 해제합니다.
- 일반 창 앱입니다. Dock에 뜨고 메인 창에서 모든 작업을 합니다. (이전의 메뉴바 전용 구성은 폐기했습니다.)

## 2. 사용자와 사용 맥락

- 주 사용자: 여러 프로젝트의 환경변수를 다루는 개발자, 로컬에 비밀값을 모아 두고 재사용하는 1인 사용자.
- 전형적 순간:
  - 새 프로젝트를 세팅하며 `.env` 값을 만들고, 터미널이나 CI 설정에 붙여넣는다.
  - 평소에는 잠가 두고, 필요할 때만 잠깐 열어 특정 키 하나를 복사한다.
  - 동료에게 특정 네임스페이스를 암호화해서 안전하게 전달한다.
- 사용 빈도: 하루에 여러 번, 짧게. 그래서 "열고, 찾고, 복사"까지의 마찰이 가장 중요합니다.

## 3. 현재 구현에서 다시 봐야 할 지점 (솔직한 진단)

지금 빌드는 기능은 동작하지만 UX와 시각 설계가 약합니다. 다음을 중심으로 다시 설계해 주세요.

1. 정보 위계가 없다: 시크릿 행에 키, 가린 값, 보기 토글, 복사 버튼, 더보기 메뉴, 선택 체크박스가 한 줄에 다 들어가 무엇이 중요한지 눈에 들어오지 않습니다. 핵심 동작(복사)과 보조 동작(편집, 삭제)의 위계를 다시 잡아야 합니다.
2. 복사 흐름이 숨어 있다: 선택 복사와 형식 변환(.env, shell, JSON, gh)이 하단 바와 작은 팝오버에 묻혀 있어 발견성이 낮습니다. 이 앱의 핵심 가치인데 가장 약하게 노출되어 있습니다.
3. 잠금과 세션 상태가 불친절하다: 잠김/해제 전환이 갑작스러운 시트로 처리되고, 남은 세션 시간 배지가 작고 의미 전달이 약합니다. "지금 안전한가, 얼마나 열려 있나"가 한눈에 보여야 합니다.
4. 온보딩이 빈약하다: 마스터 비밀번호 생성이 설명 없는 폼 하나뿐입니다. 보안 모델(값은 복구 불가, 목록은 비번 없이 보임)을 안심되게 설명하고, 복구 키 발급 흐름을 제대로 설계해야 합니다. (복구 키는 아직 미구현이니 UX부터 정의가 필요합니다.)
5. 값 가리기와 복사가 경쟁한다: 마스킹, 보기 토글, 복사가 비슷한 무게로 나열되어 혼란스럽습니다. 기본은 가린 상태이고, "보기"보다 "복사"가 더 쉬워야 합니다.
6. 빈 상태와 피드백이 약하다: 네임스페이스 없음, 시크릿 없음, 검색 결과 없음의 안내가 밋밋하고, 복사 성공이나 클립보드 자동 삭제 같은 피드백이 약한 토스트에 그칩니다.
7. 검색과 대량 작업이 미흡하다: 키가 많아지면 찾기 어렵습니다. 검색, 정렬, 선택 전체/해제 같은 기본기가 설계에 빠져 있습니다.
8. 공유 내보내기/가져오기가 다단계 시트의 나열이다: 공유 암호 설정, 파일 저장, 받는 쪽의 복호화와 재암호화가 각각의 모달로 흩어져 가이드되는 느낌이 없습니다.
9. 경고의 무게가 약하다: shell이나 gh 형식은 값이 셸 기록에 남을 수 있는데, 지금은 작은 라벨 하나로만 알립니다. 위험은 보이는 곳에서 적절한 무게로 전달해야 합니다.
10. 타이포와 간격 체계가 임시다: 폰트 크기와 여백이 경험적으로 들어가 있어 리듬이 없습니다. 타입 스케일과 스페이싱 체계를 정의해야 합니다.

## 4. 디자인 원칙 (지향점)

- 복사 우선: 가장 흔한 동작은 값을 찾아 복사하는 것입니다. 이 경로의 클릭 수와 시선 이동을 최소로 만듭니다.
- 안전은 분명하게, 조용하게: 보안 상태(잠김/해제, 남은 시간)는 항상 분명히 보이되, 겁주지 않고 차분하게 전달합니다.
- 목록은 열려 있고 값은 잠겨 있다: 이름은 비번 없이 보이고 값만 보호된다는 모델을 UI가 자연스럽게 드러냅니다.
- 절제된 강조: 강조색은 눈이 가야 할 한 곳(주요 동작, 해제 상태)에만 씁니다. 나머지는 조용히 둡니다.
- 네이티브다움: macOS 관례(사이드바, 시트, 키보드 단축키, 라이트/다크)를 따르고, 과한 그림자나 장식은 피합니다.

## 5. 정보 구조

```
Vault (기기 1대당 하나)
└─ Namespace (프로젝트/환경 단위, 예: my-api / production)
   └─ Secret (키-밸류 한 쌍, 값은 암호화)
```

- 앱 셸: 메인 창 하나. 왼쪽에 네임스페이스, 오른쪽에 선택한 네임스페이스의 시크릿.
- 설정은 창 안에서 접근(시트 또는 별도 화면). 전역 상태로 잠금/세션 표시가 항상 보입니다.

## 6. 핵심 사용자 흐름 (설계 대상)

각 흐름의 화면, 상태, 피드백, 에러까지 설계해 주세요.

1. 첫 실행과 온보딩
   - 제품 소개(한 문장), 마스터 비밀번호 생성(강도 안내), "잊으면 복구 불가" 안심 설명.
   - 복구 키 발급(1회 표시, 저장 확인). 보안 모델 요약(목록은 비번 없이 보임, 값은 비번으로만).
2. 잠금 해제
   - 비밀번호 입력, 오류 처리, 연속 실패 시 지연 안내. 해제 후 세션 시작 피드백.
3. 네임스페이스 관리
   - 생성, 이름 변경, 삭제(포함 시크릿 개수 경고), 순서 변경. 네임스페이스 전환.
4. 시크릿 보기와 복사 (핵심)
   - 목록 탐색, 검색/정렬, 값 가리기 기본, 행 단위 보기 토글, 값 1건 복사.
   - 복사 성공과 클립보드 자동 삭제 카운트다운 피드백.
5. 선택 복사와 형식 변환
   - 여러 키 선택, 형식 선택(.env, shell, JSON, gh), 결과 미리보기, 복사 또는 파일 저장.
   - gh 옵션(레포, 환경, 대상: Actions/Codespaces/Dependabot, 조직 여부) 설정.
   - shell/gh는 값이 셸 기록에 남을 수 있다는 경고를 분명히.
6. 시크릿 추가와 편집
   - 키 이름 입력, 값 입력(여러 줄 지원), `.env` 붙여넣기로 일괄 추가, 중복 키 처리.
7. 암호화 공유
   - 내보내기: 대상 선택, 공유 암호 설정, `.envman` 파일 저장.
   - 가져오기: 파일 선택, 공유 암호로 복호화, 대상 네임스페이스와 중복 정책 선택, 내 비밀번호로 재암호화.
8. 설정
   - 세션 유지 시간, 자동 잠금 조건, 클립보드 자동 삭제 시간, 마스터 비밀번호 변경, 복구 키 재발급, 데이터 초기화.
9. 잠금/세션 상태 피드백 (전역)
   - 현재 잠김/해제, 남은 세션 시간, 지금 잠그기.

## 7. 화면과 상태 목록

설계가 필요한 화면과 각 화면의 상태입니다.

- 온보딩: 소개, 비밀번호 생성, 복구 키 발급.
- 메인(잠김): 네임스페이스와 키 이름은 보이고 값은 가려진 상태, 해제 유도.
- 메인(해제): 값 보기/복사 가능 상태, 세션 타이머 표시.
- 네임스페이스: 빈 상태, 다수 상태, 생성/이름변경/삭제, 순서 변경.
- 시크릿 목록: 빈 상태, 검색 결과 없음, 다수 상태, 긴 값/여러 줄 값 처리.
- 시크릿 편집기: 추가, 편집, 중복 키 충돌.
- 선택 복사 바: 선택 개수, 형식 선택, gh 옵션, 미리보기, 경고.
- 내보내기 시트: 공유 암호 설정, 강도 안내.
- 가져오기 시트: 파일 선택, 복호화, 대상과 충돌 정책, 재암호화 진행.
- 설정: 섹션별 구성.
- 공통: 에러, 로딩/작업 중, 성공 피드백(토스트), 파괴적 동작 확인.

## 8. 보안이 UX에 거는 요구사항

- 기본은 가린 상태: 값은 기본 마스킹, 해제 상태에서만 행별로 공개 가능, 잠기면 모두 다시 가려집니다.
- 복사는 가린 상태에서도 실제 값을 넣되, 세션이 없으면 먼저 해제를 요구합니다.
- 세션: 설정한 시간 동안만 열리고 자동으로 잠깁니다. 남은 시간이 보여야 합니다.
- 클립보드 자동 삭제: 복사 후 일정 시간 뒤 지워집니다. 남은 시간을 알 수 있어야 합니다.
- 복구 불가: 비밀번호를 잊으면 값은 복구할 수 없습니다. 온보딩과 설정에서 분명히 전달합니다.
- 목록은 열려 있음: 이름은 비번 없이 보인다는 점을 사용자가 오해하지 않게 설명합니다. (키 이름 자체를 숨기는 모드는 향후 과제)

## 9. 비주얼과 브랜드 방향

현재 방향은 참고용이며, 디자이너가 다시 정의할 수 있습니다.

- 톤: 차분한 잉크 온 페이퍼 중립 배경에 절제된 그린 강조색 하나.
- 현재 강조색: 라이트 #2E7D64, 다크 #4FB58C. 상태색은 잠김/경고/위험을 위해 따로 둡니다.
- 아이콘: 현재 앱 아이콘은 그린 스퀴클에 흰색 열쇠구멍입니다. 재해석 환영합니다.
- 라이트/다크 모드 둘 다 1급으로 설계합니다.
- 키와 값은 고정폭(monospace)으로 다뤄 가독성을 높입니다.
- 타입 스케일, 스페이싱 그리드, 컴포넌트(버튼, 입력, 카드, 칩, 배지, 토스트, 시트)를 체계로 정의합니다.

## 10. 플랫폼과 기술 제약

- SwiftUI 네이티브, macOS 14 이상. 일반 창 앱(Dock 표시), 라이트/다크 지원.
- 가능하면 네이티브 컨트롤과 관례(사이드바, 시트, 메뉴, 키보드 단축키)를 사용합니다.
- 접근성: 키보드만으로 모든 동작 가능, VoiceOver 레이블, 가린 값은 보조기술에도 노출 금지, 충분한 대비.
- 한국어 기본, 문구는 현지화 가능하게 분리.
- 구현은 SwiftUI이므로, 커스텀보다 표준 컴포넌트에 얹을 수 있는 디자인이 제작 효율이 좋습니다.

## 11. 기대 산출물

1. 핵심 흐름 와이어프레임(6절 기준), 상태 포함.
2. 비주얼 시안: 주요 화면의 라이트/다크 버전.
3. 컴포넌트 라이브러리와 스펙: 타입 스케일, 색 토큰, 간격, 버튼/입력/카드/배지/토스트/시트.
4. 상호작용 명세: 잠금/해제 전환, 복사 피드백, 클립보드 카운트다운, 선택 복사, 공유 흐름.
5. 앱 아이콘(전 사이즈)과 필요한 일러스트/빈 상태 그래픽.
6. 핸드오프 포맷: Figma 파일(개발자 인스펙트 가능), 색/간격 토큰 목록.

## 12. 열린 질문 (결정 필요)

- 복구 키: 발급 방식, 보관 안내, 재설정 흐름을 어떻게 설계할까요.
- 검색/정렬: 네임스페이스 교차 검색까지 필요한가요, 네임스페이스 안으로 한정할까요.
- 메모/설명 필드: 시크릿에 비민감 메모를 둘까요.
- 키 이름 숨김 모드: v1 범위에 넣을까요, 향후로 둘까요.
- 다수 선택 동작: 복사와 내보내기 외에 일괄 삭제/이동도 필요할까요.
